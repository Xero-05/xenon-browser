# Xenon Browser 0.1.12

0.1.12 includes the functional and collaboration improvements from pull request #67 on top of 0.1.11.

- **Compact, filtered and delta observations.** `xenon_observe` and `xenon_inspect` accept `compact: true` (hoisting constant per-node metadata into top-level `nodeDefaults`, cutting typical node JSON size by ~60%), native `roles` (1–32 ARIA roles) and `interactiveOnly: true` filtering before `maxNodes` truncation. Duplicate top-level `limitations` are removed (retained under `visibility.limitations`). `xenon_observe` also accepts `sinceObservationId` to return `unchanged: true` or a `delta` (`added`, `removed`, `changed`) while issuing a fresh `observationId` and preserving live baseline references for unchanged controls.
- **Enhanced `xenon_wait`.** Wait matching is now case-insensitive across the viewport (aligned with `xenon_observe` `query`) and no longer stops scanning at 300 nodes. Callers can pass `anyOf` (1–16 candidate strings), `absent: true` (wait for text to disappear), `returnMode: "full" | "matching" | "none"` and `compact: true`.
- **Distinct Help vs. Review chrome, Attention Queue and explicit human handback.** `xenon_attention` accepts `kind: "help" | "review"` (defaulting `"review"` when `persist: true`, `"help"` otherwise). Mid-task help keeps the orange pulse; finished handbacks show a steady teal indicator and **Mark reviewed**. The toolbar displays a dynamic **Attention Queue** button jumping across windows/workspaces, and a non-activating floating per-tab banner offers **Done — resume agent** and **Hold while I work** (keeping the tab paused across the 2-second idle timer during OTP/CAPTCHA work, then clearing the request/hold and bumping `attentionResolvedEpoch` while keeping `requiresFreshObservation: true`).
- **Push-based human activity & `xenon_wait_ready`.** The broker pushes client-scoped `control.activity` frames over the local named pipe immediately on state changes (bounded and coalesced under pressure, with rate-limited adapter fallback polling). A new read-only `xenon_wait_ready` tool waits asynchronously (100–30,000 ms, optional `waitForHelpResolution: true`) until human pause or help completes without polling `xenon_control_status`.
- **Expanded `xenon_batch`, structured `staleReason` & cropped verification screenshots.** `xenon_batch` now supports element-targeted `hover` and safe page-editing `key` steps alongside `click`, `fill`, `select` and `check`. Agent-facing `stale_element` replies include an allowlisted `error.staleReason`. `xenon_screenshot` accepts optional `clip` (viewport CSS rectangle) or `candidateId` to return a cropped PNG after completing the exact same full-page multi-frame credential scan.

The unsigned Windows x64 installer and portable ZIP were built locally from this release source. Close Xenon and reconnect the MCP adapter before upgrading. Profiles and pairing configuration remain separate from application files.

The release retains the exact audited Windows-decoder engine used by 0.1.9, 0.1.10 and 0.1.11: CEF 154.0.34 / Chromium 154.0.8037.98 (`libcef.dll` SHA-256 `c997b65a258453e2351a7ce9d6e3745c74c0c83861b68fe3217c7b6ad57a3554`). It is reused without rebuilding or re-auditing its source tree. Newer stable CEF/Chromium releases exist; this release retains that security-update gap and does not claim current Chrome security parity.

H.264 requires supported Windows GPU decoding, AAC requires Windows Media Foundation, and Widevine DRM remains unsupported. There is no bundled H.264/AAC software decoder or OpenH264. Hosted CI uses the stock engine; the local release uses the Windows-decoder distribution.
