# Xenon Browser 0.1.14

0.1.14 includes the real-page compact observation pruning, transient upload popover activation and hybrid native file-chooser interception improvements from pull request #72 on top of 0.1.13.

- **Real-page `compact: true` observation pruning and compact delta computation (PR #72).** In `compact: true` mode on `xenon_observe`, `xenon_inspect` and `xenon_wait`, Xenon now omits empty-name non-interactive structural/formatting/decorative nodes (without `states`, `protected`, `candidateId`, `diagnosticId`, `inputType` or interactive/embed tags) and text-covered pure structural wrappers, omits duplicate `StaticText` children whose text is already carried verbatim by an enclosing verified interactive control or heading in the same frame, and omits `bounds` (plus redundant `boundsProvenance` and `geometryEvidence`) on non-interactive verified nodes (`StaticText`, `heading`, semantic landmarks) while keeping rounded `bounds` on interactive controls, `<canvas>`/`<iframe>`, protected nodes and uncertain candidates. Unnamed interactive controls, uncertain candidates, standalone `StaticText` body text, custom `StaticText` upload triggers (with their `ref`) and non-compact payloads remain unchanged. When `compact: true` is combined with `sinceObservationId`, deltas (`unchanged: true` or `added`/`removed`/`changed`) are now computed directly on the compacted node representation for deterministic results.
- **Transient upload popover activation and iframe-shift revalidation (PR #72).** Direct `xenon_upload` entries (including semantic `menuitem`/`option` entries and verified `StaticText` upload entries) now click directly at their verified coordinate without an intermediate hover sweep that could dismiss hover- or mouseout-sensitive popovers, while adding `DOM.getBoxModel`/`translate()` frame-translation pre-press revalidation so parent-frame layout shifts still fail closed with `stale_geometry`. Text targeting now allows `pointer-events: none` passthrough to a clickable ancestor in light and shadow DOM and, strictly during `xenon_upload`, permits a visually transparent same-document enabled `<input type="file">` overlay inside the verified text range (keeping ordinary clicks blocked). `not_actionable` and `upload_activation_failed` errors now report an allowlisted `error.reason` (`occluded`, `detached`, `fragmented_text`, `layout_moving`, `not_visible`, `outside_viewport`, `viewport_clipped`, `stale_geometry`, `human_interrupted`, etc.) without leaking website text.
- **Hybrid native file-chooser interception for agent clicks, keys and batches (PR #72).** `CefDialogHandler::OnFileDialog` now intercepts browser file choosers opened by agent-dispatched `xenon_interact(action: "click")` (by `elementRef` or screenshot coordinates), `xenon_interact(action: "key")` (`Enter`/`Space`) or `click`/`key` steps in `xenon_batch` without displaying a Windows OS modal dialog, while human-initiated clicks keep opening the normal Windows dialog. Supported `open` and `openMultiple` choosers (when the client holds `uploads` permission) return `fileChooser: { chooserId, mode: "open" | "openMultiple", acceptFilters, status: "pending" }` with strictly allowlist-sanitized `acceptFilters` (never titles, default paths or descriptions), also surfaced as `pendingFileChooser` on `xenon_observe`, `xenon_inspect` and `xenon_control_status`. Callers resolve pending choosers via `xenon_upload` with `{ chooserId, fileId }` (surviving read-only lookups such as `xenon_files`/`xenon_folders`/`xenon_observe`) or cancel them via `{ chooserId, cancel: true }`. Unsupported directory/save choosers (`status: "rejected"`, `reason: "unsupported_chooser_mode"`) and unauthorized choosers (`status: "blocked"`, `reason: "uploads_not_permitted"`) are canceled immediately without showing a Windows modal. In `xenon_batch`, a pending chooser halts remaining steps (`status: "stopped"`, `stoppedAt`, `stopReason: "file_chooser_pending"`), and any pending chooser auto-cancels immediately on navigation, tab close/shutdown, human page activity, protected authentication, ownership handoff/release/disconnect, policy revocation, a 60-second TTL or any other mutating tab command.

The unsigned Windows x64 installer and portable ZIP were built locally from this release source. Close Xenon and reconnect the MCP adapter before upgrading. Profiles and pairing configuration remain separate from application files.

The release retains the exact audited Windows-decoder engine used by 0.1.9, 0.1.10, 0.1.11, 0.1.12 and 0.1.13: CEF 154.0.34 / Chromium 154.0.8037.98 (`libcef.dll` SHA-256 `c997b65a258453e2351a7ce9d6e3745c74c0c83861b68fe3217c7b6ad57a3554`). It is reused without rebuilding or re-auditing its source tree. Newer stable CEF/Chromium releases exist; this release retains that security-update gap and does not claim current Chrome security parity.

H.264 requires supported Windows GPU decoding, AAC requires Windows Media Foundation, and Widevine DRM remains unsupported. There is no bundled H.264/AAC software decoder or OpenH264. Hosted CI uses the stock engine; the local release uses the Windows-decoder distribution.
