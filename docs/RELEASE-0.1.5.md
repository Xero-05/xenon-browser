# Xenon Browser 0.1.5

This release adds Default and Sensitive saved-account groups. A client or workspace with **Allow all Default passwords** can use every Default account at the exact HTTPS origin the vault stores for it, including logins saved later, without a separate grant for each one. Sensitive accounts still need an individual grant. The Save bubble, **Save account** and **Import CSV** ask for the group, and **Make sensitive**/**Make default** in Controls → Passwords moves an account; moving it to Sensitive withdraws group access immediately. Accounts saved before this release start as Sensitive, so upgrading gives no agent new account access. Groups are native-only: MCP cannot read or change them, and `clientPolicy` reports only the boolean `defaultAccounts`.

Passkeys now use Chromium's WebAuthn support and the Windows authenticator, and only the human can start a ceremony. Tabs the human controls are unchanged. In a tab an agent controls, a request reaches Windows only right after the human's own click or key press in that tab; a request caused by an agent action is refused with `NotAllowedError` before Windows is asked, and `xenon_control_status` reports `passkeyNeedsHuman` until the tab navigates. A ceremony the human starts pauses agent input until it ends. Tabs Xenon opens for a URL now install this gate before the website loads, and cross-origin frames wait for it; a popup's first document is not covered.

The Extensions, Controls and menu buttons, the find bar and the page elements panel no longer smear while the window is resized. The release smoke test and the worker-lifecycle suite now retry the transient `page_changed` read that can follow tab creation; mutations are never retried.

The Windows x64 ZIP and setup executable are unsigned and include SHA-256 sidecars. Close Xenon and reconnect the MCP adapter after upgrading. Dependency pins are unchanged. The [CEF index](https://cef-builds.spotifycdn.com/index.json), checked October 15, still lists the pinned CEF 154.0.34 / Chromium 154.0.8037.98 as its highest stable Windows x64 build; CEF 156 is available only as beta. Chrome's Windows stable channel is at 156.0.8078.36, so this release retains the upstream CEF security-update lag and does not claim parity with current Chrome. Unsigned hashes establish byte integrity, not publisher identity.

The published files are the artifacts of the merged release commit's Windows CI run, which builds the browser, runs the native and adapter tests, verifies the packaged archive, tests the isolated installer, smoke-tests the extracted ZIP and runs eight live browser suites, including the passkey gate, on the packaged DLL. The password-group controls have not been displayed or clicked in a validation run, and no suite performs a real WebAuthn ceremony through Windows Hello, a security key or a phone. The toolbar repaint fix was confirmed by a manual drag resize of the toolbar buttons; the find bar and elements panel were not checked during a live drag. Physical input, high contrast, other DPI, assistive technology and real-account acceptance remain unverified; see [testing](TESTING.md).
