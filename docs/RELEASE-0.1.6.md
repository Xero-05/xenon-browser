# Xenon Browser 0.1.6

**Withdrawn.** 0.1.6 was published on October 17, 2026 and switched back to a draft the same day because codec licensing for distributing its built-in H.264 and AAC decoders had not been confirmed. Its files and tag are kept unchanged, and v0.1.5 is the latest published release. The notes below describe the withdrawn files.

This release fills in everyday browser features, plays H.264 and AAC video, and lets agents ask the person for help.

**Agents can ask for your help.** The new `xenon_attention` MCP tool lets an agent mark a tab it controls as needing you, for example for a CAPTCHA, MFA, a passkey or an approval. The tab's border pulses orange in the sidebar until you have been at it, and a background window's taskbar button flashes. **Settings → Agents** can also show a Windows notification, off by default, that opens the tab. A request is metadata only: it does not pause the agent or change ownership. **Dismiss help request** withdraws it. Xenon now exposes 27 MCP tools.

**Address box.** As you type, Xenon suggests pages from the workspace's history and bookmarks and completes visited sites inline, as Chrome and Edge do. Matching runs on your device; nothing is sent to a search provider until you open a search. **Settings** chooses the search engine: Google, Bing, DuckDuckGo, Brave Search, Ecosia, Startpage or Baidu. A site-information button at the left of the address box shows the connection and certificate, lists the site's cookies without their values, deletes cookies or all site data, and manages per-site Location, Camera, Microphone, Notifications, Pop-ups and Sound settings. **Menu → Site settings** opens the same controls.

**Full screen, icons and other apps.** **F11** hides Xenon's toolbar and sidebar, and a website's full-screen request, such as a video player's, takes over the screen in a tab you control; **Esc** ends it. Tabs show site icons. `mailto:` and meeting-app links open their registered Windows app after a native prompt naming the site, the app and the link. Agents cannot start these links, and schemes that run programs, files, searches or diagnostics are never offered.

**Screen sharing.** Video-call sites can share your screen after a native prompt that explains Xenon shares every display, not a single window. Agents cannot start sharing, and their screenshots of a sharing tab fail with the new `screen_sharing` error. A red icon marks a sharing tab.

**Default browser, bookmarks, history and import.** The installer registers Xenon with Windows for `http` and `https` links, and **Settings** opens Windows' Default apps page for Xenon. A link from Windows opens in a new Personal tab or starts Xenon with it. **Ctrl+Shift+O** opens a bookmark manager with folders and search; history can be searched and individual visits deleted; **Ctrl+Shift+Del** clears a workspace's browsing data for a time range. Bookmarks and history import from Chrome, Edge, Brave, Vivaldi or Chromium profiles, or from an exported bookmark file. Passwords and cookies are never read; passwords still come in through CSV import.

**Polish.** The agent cursor has a status-colored outline and glow, the selected tab and page share one continuous glow while an agent controls them, and sidebar **+**, **…** and close buttons have a distinct hover fill. On Chromium's **Your connection is not private** page, **Learn more** now opens Xenon's guide instead of Google's Chrome Help Center, and the suggestion to turn on Chrome's enhanced protection, which did nothing in Xenon, is hidden. Combo boxes follow Dark mode, and browser panels size correctly at 125% display scaling.

**Website video.** H.264 and AAC now play, so MP4 video and streams that use those codecs work alongside WebM. Packages use a CEF engine built from source with Chromium's proprietary codecs enabled, at the same CEF 154.0.34 / Chromium 154.0.8037.98 revisions as before; its recipe is pinned in `cef.mediaSourceBuild` in `dependencies.lock.json` and described in [BUILD](BUILD.md#website-video-codecs). This adds codecs, not DRM: protected streaming services that need Widevine still do not play.

The Windows x64 ZIP and setup executable are unsigned and include SHA-256 sidecars. Close Xenon and reconnect the MCP adapter after upgrading. Dependency pins are unchanged; the engine comes from the source recipe already pinned in the lockfile. The [CEF index](https://cef-builds.spotifycdn.com/index.json), checked October 17, still lists the pinned CEF 154.0.34 / Chromium 154.0.8037.98 as its highest stable Windows x64 build; CEF 156 is available only as beta. Chrome's Windows stable channel is at 156.0.8078.36, so this release retains the upstream CEF security-update lag and does not claim parity with current Chrome. Unsigned hashes establish byte integrity, not publisher identity.

Hosted CI can build only the stock engine, which lacks H.264 and AAC, so the published files were built and packaged on a maintainer's Windows 11 machine from the merged release source with the codec-enabled engine. Before publication they passed the native and adapter tests, package verification, the isolated installer tests and the extracted-package smoke test, and the packaged DLL passed the eight live browser suites that CI runs plus the H.264/AAC and WebM playback suites. CI's own run on the release commit used the stock engine; its artifacts are not published. The address-suggestion, site-information, browser-essentials and agent-gate suites are local desktop suites that were not rerun for this release; their earlier local results are in [testing](TESTING.md). Help requests have native and adapter tests and a manual check on a disposable profile, but no live suite yet. Full screen was not entered, screen sharing was not allowed, the Import window was not opened and default-browser registration was checked only in the installer fixture's isolated key. Physical input, high contrast, other DPI, assistive technology, real websites' video and real-account acceptance remain unverified.
