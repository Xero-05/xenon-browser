# Xenon Browser 0.1.13

0.1.13 includes the rendered-evidence, focused-typing, agent-efficiency and multi-worker reliability improvements from pull requests #69 and #70 on top of 0.1.12.

- **Scrolled textarea visibility and transparent-border occlusion fixes (PR #69).** Guarded `inset_clip()` in uncertain-node filtering so `clip-path: none` no longer drops controls scrolled below the first screen on `html, body { height: 100% }` layouts, while preserving independently verified `<label>` names on uncertain inputs. Multi-line `<textarea>` elements straddling a viewport edge can now verify an unoccluded 2×2 patch inside a substantial visible viewport slice (`geometryEvidence: "unoccluded_visible_patch"`). Transparent decorative boxes painted only with borders and/or an outward outline (`outline-offset >= 0`) no longer cause false `boundedPaintOcclusion`, and pure 2D `matrix3d` translations are handled directly.
- **Screenshot-grounded `action: "type"` fallback (PR #69).** `xenon_interact` accepts `action: "type"` (1–65,536 UTF-8 bytes without disallowed control characters; forbids `elementRef` and coordinates; excluded from `xenon_batch`). Native enforcement requires a current screenshot `observationId` (already cleared by the full multi-frame credential scan), unchanged visual viewport, owner/generation/human-pause/operationId checks, and an isolated-world check on `document.activeElement` refusing password, one-time-code, `-webkit-text-security`, disabled, read-only, inert, embedded-frame, hidden/low-opacity, off-viewport and occluded targets before dispatching page-only text insertion (`Input.insertText`).
- **Per-session `--evidence-root` export and file metadata (PR #70).** The MCP adapter CLI accepts `--evidence-root <dir>` (mutually exclusive with `--evidence-dir <dir>`), lazily creating a fresh unique private (`0700`) subdirectory (`<timestamp>-<uuid>`) on the first accepted tool call without requiring callers to pick a fresh path each run. Exported MCP replies include `evidenceExport: { requestId, status: "saved", directory, files }` with the exact saved `.json` and `.png` filenames inside `directory`.
- **Click popup discovery, `observeAfter` and `scroll` in `xenon_batch` (PR #70).** Clicking a control (in `xenon_interact` or `xenon_batch`) that spawns one or more new owned tabs or popups in the same `controlGroupId` returns `createdTabs: [{ tabId, ownershipGeneration, controlGroupId }]` directly on the reply without a follow-up `xenon_tabs` poll. `xenon_interact` and `xenon_batch` accept an optional text-only `observeAfter` object (`maxNodes`, `query`, `roles`, `interactiveOnly`, `compact`, `sinceObservationId`, `settleMs`) to attach a fresh post-action `observation` (or `observationError` without failing or retrying the mutation) after clean completion, and `xenon_batch` now supports `scroll` steps (`direction`, optional `amount` 1–10,000).
- **Delta `xenon_inspect` and tighter `compact: true` observations (PR #70).** `xenon_inspect` supports `sinceObservationId` to return `unchanged: true` or a `delta` (`added`, `removed`, `changed`) alongside the fresh screenshot. `compact: true` hoists repeated per-node defaults into `nodeDefaults`, condenses static `visibility.limitations` (and clean `textSafety.limitation`) to concise machine-readable codes, rounds CSS pixel bounds (integer when exact, 1 decimal place otherwise), and deduplicates redundant container text already emitted verbatim by preserved child nodes in the same observation (never altering interactive controls, `StaticText` upload entries, headings, uncertain candidates or non-compact payloads).
- **Transient capture settle retry and per-worker `operationId` scoping (PR #70).** When `xenon_observe` or `xenon_inspect` encounters transient `privacy_guard_initializing` or same-document `inspection_changed` (with no credential protection, screen sharing, human activity, ownership change or cross-document navigation), the engine performs at most one bounded 200 ms settle retry before failing closed. Mutation `operationId` deduplication is scoped per `(clientId, agentSessionId)` so parallel workers sharing the same paired client do not collide, and `xenon_operation` accepts optional `agentSessionId` (returning `OPERATION_AMBIGUOUS` when multiple workers reused an ID).

The unsigned Windows x64 installer and portable ZIP were built locally from this release source. Close Xenon and reconnect the MCP adapter before upgrading. Profiles and pairing configuration remain separate from application files.

The release retains the exact audited Windows-decoder engine used by 0.1.9, 0.1.10, 0.1.11 and 0.1.12: CEF 154.0.34 / Chromium 154.0.8037.98 (`libcef.dll` SHA-256 `c997b65a258453e2351a7ce9d6e3745c74c0c83861b68fe3217c7b6ad57a3554`). It is reused without rebuilding or re-auditing its source tree. Newer stable CEF/Chromium releases exist; this release retains that security-update gap and does not claim current Chrome security parity.

H.264 requires supported Windows GPU decoding, AAC requires Windows Media Foundation, and Widevine DRM remains unsupported. There is no bundled H.264/AAC software decoder or OpenH264. Hosted CI uses the stock engine; the local release uses the Windows-decoder distribution.
