# Xenon Browser

[English](README.md) · **简体中文**

<img src="assets/branding/xenon-icon.png" alt="Xenon Browser 图标" width="96" height="96">

**让用户与 MCP 智能体协作的开源 Windows 浏览器。**

Xenon 将 Chromium 网页浏览与原生智能体控制结合起来，让外部智能体能够查看页面、操作网站，并交接正在运行的标签页。你可以决定哪些 MCP 客户端可以连接、可以使用哪些工作区，以及可以访问哪些已保存账号或本地文件。模型由你的 MCP 宿主提供；Xenon 不内置大语言模型，也不需要模型 API 密钥。

**当前版本：0.1.0-alpha.14 · Windows 10/11 x64 · 未签名 Alpha 版本。** 提供当前用户安装程序和便携 ZIP 包，并支持原生更新检查。参见[发行说明](docs/RELEASE_NOTES.md)和[验证范围](docs/TESTING.md)。

## Xenon 的功能

| 功能 | 当前行为 |
| --- | --- |
| **日常浏览** | 原生地址／搜索栏、后退／前进／刷新、页面查找、缩放、书签、历史记录、下载、打印／PDF 和网站权限。标签页支持关闭按钮、鼠标中键关闭和键盘快捷键。 |
| **原生界面** | 按工作区分组的标签页、可调整宽度的侧边栏、可保存的系统／浅色／深色主题、控制权状态文字与边框，以及不会移动 Windows 鼠标的智能体光标。 |
| **独立工作区** | 持久工作区分别保存 Cookie 和本地存储。可以创建、重命名、配置工作区，或主动将其共享给已配对客户端。仅供用户使用的隐私工作区采用内存配置文件。 |
| **并行智能体** | 多个已配对宿主，或同一宿主下的多个工作会话，可以同时操作不同标签页。每个标签页／控制组只有一个可写控制者；智能体自动获得其所创建标签页的控制权。 |
| **实时交接** | 将标签页及其关联弹出标签页交给已授权的工作会话或用户。控制权提交不会发出浏览器命令，已加载页面、表单状态、滚动位置和连接保持原样。 |
| **人机协作** | 在智能体控制的页面上点击、输入、滚动或拖动，会临时暂停智能体，但保留其控制权。排队操作被取消；继续之前必须获取新的页面证据。原生 **Take ownership（接管）** 可将控制权持续保留给你。 |
| **页面证据与操作** | 获取当前视口内已渲染文本的有界观察结果和仅包含网页的截图；支持导航、点击、悬停、文本／日期填写、选择、复选框、按键、滚动、完整拖动、文本等待及 JavaScript 对话框。 |
| **已保存账号** | 各工作区共用的 Windows DPAPI 加密凭据库、手动保存／移除、带脱敏预览和冲突处理选项的 Chrome／Edge／Firefox CSV 导入、针对受支持手动登录的原生 Save/Update 提示，以及不提交表单的用户填充。智能体通过明确授权的不透明账号 ID，向精确的 HTTPS 来源请求受保护登录。 |
| **限定文件访问** | 原生文件／文件夹授权、有界文件列表、通过已观察到的文件输入框或可见上传入口选择文件，以及工作区下载元数据。智能体使用不透明句柄；不提供无限制的文件系统或 Shell 访问。 |
| **恢复与生命周期** | 持久保存的配对和授权、工作会话重连／恢复与退役、明确执行的 URL 会话恢复，以及用于检查不确定变更结果且不会自动重放操作的有界操作日志。 |
| **安装与更新** | 带目标文件夹选择的当前用户安装程序、完整便携 ZIP 包，以及从固定发行仓库进行的原生更新检查／下载和大小／SHA-256 校验。安装必须由用户决定，并正常关闭浏览器。 |

当前页面的边框使用**青绿色**表示可用的智能体控制者，**橙色**表示因用户输入而暂停，**灰色**表示用户控制或智能体不可用。Controls 分为 **Clients（客户端）**、**Workspaces（工作区）** 和 **Passwords（密码）** 三个部分，也可撤销访问、管理资源、处理用户触发的网站对话框，以及通过 **Stop all agents（停止所有智能体）** 停止本次浏览器运行中的智能体控制。锁定 Windows 会话也会锁定凭据库并停止智能体控制。

## 快速开始

1. 从发行页面下载**未签名的 Windows 安装程序**和对应的 `.sha256` 文件。校验后，选择本地固定驱动器上一个空的、可写的程序文件夹。[快速入门](docs/GETTING_STARTED.md#1-install-xenon)提供具体命令和安装说明。发行包已包含 Node 和 MCP 适配器。
2. 从开始菜单打开 **Xenon Browser**。每次全新启动都会在 **Personal** 工作区打开一个空白标签页。通过地址栏正常浏览网站。
3. 使用 **Ctrl+Shift+X**、侧边栏底部的滑块按钮，或网页右键菜单打开 **Xenon Controls**。
4. 按照[配对与宿主配置](docs/GETTING_STARTED.md#3-pair-your-mcp-host)连接本地 stdio MCP 宿主。妥善保管生成的配对文件；对独立信任的宿主分别配对。
5. 配置客户端权限，然后共享现有工作区，或明确启用自动创建工作区。智能体要执行页面操作，客户端策略和工作区访问权限都必须允许。

新配对的客户端默认**只读**，自动创建工作区功能关闭，配额为**四个已连接工作会话**和**四个自动创建的工作区**。客户端策略设定权限上限；各工作区还可进一步限制权限以及继承的文件／账号资源。保存账号或共享工作区不会自动授予凭据库访问权限。

启用页面交互和自动创建工作区后，可以尝试：

> 使用 Xenon 在新工作区打开 https://example.com，查看可见页面，并告诉我页面主标题。保持标签页打开，完成后让工作会话退役。

常见顺序是 `xenon_worker_create` → `xenon_tab_create` → `xenon_observe`，随后按需要执行绑定页面证据的操作，并在完成后调用 `xenon_worker_retire`。退役会释放工作会话配额，同时保留标签页、工作区和网站状态；该工作会话句柄无法恢复。

使用便携 ZIP 包时，先校验，再解压**完整压缩包**并运行 `Xenon.exe`。可执行文件、DLL、资源、语言目录、适配器和随附的 Node 运行时必须保存在一起。

## MCP 功能

Xenon 通过严格校验参数的 TypeScript MCP stdio 适配器提供 **24 个工具**。工具响应包含结构化 JSON 和 JSON 文本；截图还包含 MCP 图像内容。[智能体指南](docs/AGENT_GUIDE.md)提供可复制的宿主指令，[MCP 参考](docs/MCP.md)说明参数、页面证据和错误处理。

| 工具 | 用途 |
| --- | --- |
| `xenon_worker_create`, `xenon_workers`, `xenon_worker_resume`, `xenon_worker_retire` | 创建、列出、重连和退役逻辑工作会话。 |
| `xenon_workspaces` | 列出已授权给配对客户端的工作区。 |
| `xenon_tabs`, `xenon_tab_create`, `xenon_tab_close` | 在授权范围内列出、打开和关闭标签页。 |
| `xenon_control_status`, `xenon_control` | 查看控制权，并使用当前控制权版本号获取、释放或交接控制权。 |
| `xenon_activity` | 读取可信的用户活动与暂停元数据，不包含输入值或页面文本。支持的宿主还可订阅 `xenon://control/activity`。 |
| `xenon_observe`, `xenon_screenshot` | 获取有界视口证据和仅包含网页的图像，并检查文档身份及证据是否仍有效。 |
| `xenon_navigate`, `xenon_interact`, `xenon_wait`, `xenon_dialog` | 导航、执行有限时长的完整操作、等待已渲染文本，以及处理智能体控制的 JavaScript 对话框。原生安全提示由用户处理。 |
| `xenon_accounts`, `xenon_login` | 列出已授权账号的元数据，并请求受保护登录，不返回凭据库中的用户名或密码。 |
| `xenon_folders`, `xenon_files`, `xenon_upload`, `xenon_downloads` | 查找已批准句柄、选择已授权的上传文件，以及查看下载元数据。 |
| `xenon_operation` | 在超时或断开连接后检查保留的变更操作，再决定下一步。 |

观察和文本等待使用同一套已渲染视口过滤规则，并报告覆盖范围、遗漏和截断情况。隐藏标签和视口外文本不会返回；要查看更多内容，需滚动后重新观察。元素操作使用新获取的元素引用；坐标操作使用匹配的截图及其报告的 CSS 像素比例。受支持的日期输入框接受规范的 `YYYY-MM-DD` 值。

浏览器默认上限为**同时连接 16 个工作会话**和 **64 个标签页**，还受各客户端配额限制。用户可在启动时将全局工作会话上限设为 1–256；MCP 调用者不能更改此设置。这些是并发上限，不是累计创建上限。不同标签页可并行运行，同一标签页内的输入按顺序执行。

## 工作区、会话延续与控制权

要继续使用相同 Cookie、网站登录或已记住的 MFA 会话，应复用已授权的工作区。共享会使获准客户端能够使用该工作区现有的网站会话。独立配置文件隔离浏览器存储，但使用同一远程账号的会话仍可能修改同一份在线数据。

用户页面输入会暂停智能体操作，通常持续到最后一次活动约两秒后；按键／鼠标按钮未释放、IME 输入法组合或用户打开的对话框仍在处理时，暂停会延长。控制权保持不变。活动通知和工具响应帮助宿主获知暂停；原生执行层会取消尚未派发的操作。继续操作需要确认当前已解除暂停，并获取新的页面证据。**Take ownership（接管）**、**Give to agent（交给智能体）** 和智能体实时交接属于明确的控制权变更。

关闭最后一个标签页会保留已保存工作区。空的已保存工作区在重启后仍显示在侧边栏中，可用于打开新的、由用户控制的空白标签页。关闭 Xenon 不会使网站退出登录：持久工作区会保留 Cookie，包括会话 Cookie。**Restore last session（恢复上次会话）** 会在用户明确选择后，以用户控制权重新加载符合条件的已保存 URL，排除隐私／受保护页面；它不会恢复未保存的表单状态、渲染进程内存或旧的智能体操作。实时交接则保留当前正在运行的页面。

原生 **Remove workspace（移除工作区）** 需要确认，不能用于移除 Personal；它会关闭该工作区的标签页、取消下载，并撤销其授权。共享凭据库账号、已完成下载和原始上传文件仍然保留。配置文件清理范围受限，遇到锁定或不安全路径时可能延后；这不等于安全擦除或网站退出登录。工作会话退役和关闭标签页是独立操作。

## Alpha 版本的边界

- **平台与宿主：** 支持 Windows x64 和外部本地 stdio MCP 宿主。仅支持远程连接的宿主需要其他传输方式；视觉任务需要支持图像的客户端／模型。不内置模型、不提供云同步或已签名安装程序，也不保证专有 DRM 或任意扩展兼容性。
- **凭据：** 已保存账号功能仅支持有限类型的 HTTPS 表单。MFA、通行密钥、CAPTCHA、嵌入式登录组件及特殊流程需要用户处理。受保护身份验证期间不返回观察结果／截图；原生 Save/Fill/Resume 确认无法通过 MCP 接受。测试夹具覆盖不代表已完整验证真实鼠标键盘操作下的凭据提示，也不代表所有真实网站兼容。
- **文件与结果：** 不支持目录上传、File System Access API 选择器或跨框架委托文件选择器。选择文件不代表服务器已收到文件；派发操作不代表网站任务成功。采取后续操作前，应检查不确定操作及页面状态。
- **信任：** 所有网站文本、图像、对话框和下载名称都是不可信内容。过滤隐藏内容无法使模型免受提示注入，也无法识别所有可见秘密。工作区授权会开放相应页面会话。DPAPI 无法防御以同一 Windows 用户身份运行的恶意软件。本 Alpha 版本尚未接受独立安全审计。请阅读[安全边界](docs/SECURITY.md)。
- **更新与验证：** 更新需要用户决定安装并重启，不保留正在运行的渲染进程状态。发布的哈希用于依据发行元数据验证下载，不能证明发布者身份。合成测试和原生测试驱动覆盖与实际界面操作覆盖分别记录；完整菜单／对话框、高对比度和多 DPI 验收矩阵尚未完成。参见[测试说明](docs/TESTING.md)。

## 架构、构建与贡献

Xenon 使用 **C++20**、**CEF 的沙箱化 Chrome 运行时**、**原生能力代理**和**严格校验参数的 TypeScript MCP 适配器**。宿主通过 stdio 启动适配器，适配器再通过当前用户的 Windows 命名管道连接代理。原生代码负责执行客户端、工作区、控制权、账号和文件授权检查。不提供模型指定的 JavaScript、原始 CDP、隐藏 DOM 提取或操作系统控制接口。

准备 Windows 10/11 x64、Visual Studio 2022 C++ Build Tools 及 Windows SDK／CMake、Node 24、npm、Git 和 7-Zip（参见[前置条件](docs/BUILD.md)）后：

```powershell
./scripts/bootstrap.ps1
npm.cmd ci
./scripts/build.ps1 -Test
./build/app/Release/Xenon.exe
```

将匹配的运行时文件保留在可执行文件旁。按照 [TESTING.md](docs/TESTING.md)选择适合改动的检查，并遵循[贡献者指令](AGENTS.md)。不要针对共享输出并发运行构建或桌面测试套件。
