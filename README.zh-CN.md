# Xenon Browser

[English](README.md) · **简体中文**

<img src="assets/branding/xenon-icon.png" alt="Xenon Browser 图标" width="96" height="96">

**一个开源的 Windows 浏览器，让人和 MCP 智能体一起上网。**

Xenon 把 Chromium 网页浏览和原生智能体控制结合起来。外部智能体可以查看页面、操作网站，还能接手正在运行的标签页。哪些 MCP 客户端可以连接、能用哪些工作区、能访问哪些已保存账号或本地文件，全部由你决定。模型由你自己的 MCP 宿主提供：Xenon 不内置大语言模型，也不需要模型 API 密钥。

**当前版本：0.1.0-alpha.16 · Windows 10/11 x64 · 未签名 Alpha 版本。** 提供当前用户安装程序和便携 ZIP 包，并支持原生更新检查。参见[发行说明](docs/RELEASE_NOTES.md)和[验证范围](docs/TESTING.md)。

## Xenon 能做什么

| 功能 | 当前行为 |
| --- | --- |
| **日常浏览** | 原生地址／搜索栏、后退／前进／刷新、页面查找、缩放、书签、历史记录、下载、打印／PDF 和网站权限。标签页支持关闭按钮、鼠标中键关闭和键盘快捷键。 |
| **原生界面** | 支持英语和简体中文；首次启动提供语言选择和快速导览。界面包含按工作区分组的标签页、可调整宽度的侧边栏、可保存的系统／浅色／深色主题、控制权状态文字与边框，以及不会移动 Windows 鼠标的智能体光标。 |
| **独立工作区** | 持久工作区各自保存 Cookie 和本地存储。你可以创建、重命名、配置工作区，也可以主动把它共享给已配对客户端。仅供用户使用的隐私工作区采用内存配置文件。 |
| **并行智能体** | 多个已配对宿主，或同一宿主下的多个工作会话，可以同时操作不同标签页。每个标签页／控制组只有一个可写控制者；智能体自己创建的标签页自动归它控制。 |
| **实时交接** | 把标签页及其关联弹出标签页交给已授权的工作会话或用户。交接只改控制权，不会向浏览器发出任何命令：已加载的页面、表单状态、滚动位置和连接全部原样保留。 |
| **人机协作** | 在智能体控制的页面上点击、输入、滚动或拖动，会临时暂停该智能体，但控制权不变。排队中的操作会被取消，继续之前必须重新获取页面证据。原生 **Take ownership（接管）** 可以让你长期保留控制权。 |
| **页面证据与操作** | 获取当前视口内已渲染文本的有界观察结果，以及只含网页内容的截图；支持导航、点击、悬停、文本／日期填写、选择、复选框、按键、滚动、完整拖动、文本等待和 JavaScript 对话框。 |
| **已保存账号** | 各工作区共用同一个 Windows DPAPI 加密凭据库；支持手动保存／移除、带脱敏预览和冲突处理选项的 Chrome／Edge／Firefox CSV 导入、针对受支持手动登录的原生 Save/Update 提示，以及不会自动提交表单的用户填充。智能体只能凭明确授权的不透明账号 ID，向精确的 HTTPS 来源请求受保护登录。 |
| **限定文件访问** | 原生文件／文件夹授权、有界文件列表、通过已观察到的文件输入框或可见上传入口选择文件，以及工作区下载元数据。智能体只能使用不透明句柄，没有不受限制的文件系统或 Shell 访问权限。 |
| **恢复与生命周期** | 持久保存的配对和授权、工作会话的重连／恢复与退役、明确执行的 URL 会话恢复，以及有界操作日志——用它检查结果不确定的变更，且不会自动重放。 |
| **安装与更新** | 带目标文件夹选择的当前用户安装程序、完整便携 ZIP 包，以及从固定发行仓库进行的原生更新检查／下载和大小／SHA-256 校验。安装必须由用户决定，并正常关闭浏览器。 |

当前页面用边框颜色表示控制权：**青绿色**表示有可用的智能体控制者，**橙色**表示因用户输入而暂停，**灰色**表示由用户控制或智能体不可用。Controls 分为 **Clients（客户端）**、**Workspaces（工作区）** 和 **Passwords（密码）** 三个部分，你还可以在这里撤销访问、管理资源、处理用户触发的网站对话框，以及用 **Stop all agents（停止所有智能体）** 结束本次浏览器运行中的智能体控制。锁定 Windows 会话时，凭据库会一并锁定，智能体控制也会停止。

## 快速开始

1. 从发行页面下载**未签名的 Windows 安装程序**和对应的 `.sha256` 文件。校验无误后，在本地固定驱动器上选一个空的、可写的程序文件夹。[快速入门](docs/GETTING_STARTED.md#1-install-xenon)里有具体命令和安装说明。发行包已包含 Node 和 MCP 适配器。
2. 从开始菜单打开 **Xenon Browser**。首次启动先选择 **English / 简体中文**，然后跟随或跳过简短导览，在 **Personal** 工作区开始浏览或打开 GitHub 入门文档。以后可通过 **菜单 → 快速导览** 再次查看；每次正常启动都会打开一个空白标签页。
3. 用 **Ctrl+Shift+X**、侧边栏底部的滑块按钮，或网页右键菜单打开 **Xenon Controls**。
4. 按照[配对与宿主配置](docs/GETTING_STARTED.md#3-pair-your-mcp-host)连接本地 stdio MCP 宿主。妥善保管生成的配对文件；对每个独立信任的宿主分别配对。
5. 配置客户端权限，然后共享一个已有工作区，或明确开启自动创建工作区。要让智能体操作页面，客户端策略和工作区访问权限必须同时允许。

新配对的客户端默认**只读**，自动创建工作区处于关闭状态，配额为**四个已连接工作会话**和**四个自动创建的工作区**。客户端策略决定权限上限，各工作区还能进一步收紧权限及其继承的文件／账号资源。保存账号或共享工作区，都不会自动授予凭据库访问权限。

开启页面交互和自动创建工作区之后，可以这样试：

> 用 Xenon 在新工作区打开 https://example.com，查看可见页面，并告诉我页面主标题。保持标签页打开，完成后让工作会话退役。

常见流程是 `xenon_worker_create` → `xenon_tab_create` → `xenon_observe`，按需执行绑定页面证据的操作，最后调用 `xenon_worker_retire`。退役会释放工作会话配额，同时保留标签页、工作区和网站状态；该工作会话句柄无法再恢复。

如果使用便携 ZIP 包，先校验，再解压**完整压缩包**并运行 `Xenon.exe`。可执行文件、DLL、资源、语言目录、适配器和随附的 Node 运行时必须放在一起。

## MCP 功能

Xenon 通过严格校验参数的 TypeScript MCP stdio 适配器提供 **24 个工具**。工具响应包含结构化 JSON 和 JSON 文本，截图还会附带 MCP 图像内容。[智能体指南](docs/AGENT_GUIDE.md)提供可直接复制的宿主指令，[MCP 参考](docs/MCP.md)说明参数、页面证据和错误处理。

| 工具 | 用途 |
| --- | --- |
| `xenon_worker_create`, `xenon_workers`, `xenon_worker_resume`, `xenon_worker_retire` | 创建、列出、重连和退役逻辑工作会话。 |
| `xenon_workspaces` | 列出已授权给该配对客户端的工作区。 |
| `xenon_tabs`, `xenon_tab_create`, `xenon_tab_close` | 在授权范围内列出、打开和关闭标签页。 |
| `xenon_control_status`, `xenon_control` | 查看控制权，并凭当前控制权版本号获取、释放或交接控制权。 |
| `xenon_activity` | 读取可信的用户活动与暂停元数据，不含输入内容和页面文本。支持的宿主还可订阅 `xenon://control/activity`。 |
| `xenon_observe`, `xenon_screenshot` | 获取有界视口证据和只含网页内容的图像，并检查文档身份与证据是否仍然有效。 |
| `xenon_navigate`, `xenon_interact`, `xenon_wait`, `xenon_dialog` | 导航、执行有限时长的完整操作、等待已渲染文本，以及处理智能体控制的 JavaScript 对话框。原生安全提示仍由用户处理。 |
| `xenon_accounts`, `xenon_login` | 列出已授权账号的元数据，并请求受保护登录；不会返回凭据库中的用户名或密码。 |
| `xenon_folders`, `xenon_files`, `xenon_upload`, `xenon_downloads` | 查找已批准的句柄、选择已授权的上传文件，以及查看下载元数据。 |
| `xenon_operation` | 在超时或断开连接后检查保留的变更操作，再决定下一步。 |

观察和文本等待使用同一套已渲染视口过滤规则，并会报告覆盖范围、遗漏和截断情况。隐藏标签和视口外的文本不会返回；想看更多内容，需要滚动后重新观察。元素操作要使用新获取的元素引用；坐标操作要使用匹配的截图及其报告的 CSS 像素比例。受支持的日期输入框接受规范的 `YYYY-MM-DD` 值。

浏览器默认上限为**同时连接 16 个工作会话**和 **64 个标签页**，并额外受各客户端配额限制。用户可在启动时把全局工作会话上限设为 1–256，MCP 调用者无法更改。这些是并发上限，不是累计创建上限。不同标签页可以并行运行，同一标签页内的输入按顺序执行。

## 工作区、会话延续与控制权

如果你想继续使用相同的 Cookie、网站登录状态或已记住的 MFA 会话，就复用已授权的工作区。共享工作区会让获准客户端用上该工作区已有的网站会话。独立配置文件能隔离浏览器存储，但使用同一远程账号的会话仍可能改动同一份线上数据。

用户在页面上的输入会暂停智能体操作，通常在最后一次活动约两秒后结束；如果按键／鼠标按钮还没释放、IME 正在组合输入，或用户打开的对话框仍处于活动状态，暂停会相应延长。控制权在此期间保持不变。活动通知和工具响应会帮助宿主察觉暂停；原生执行层会取消尚未派发的操作。要继续操作，必须先确认暂停已解除，并重新获取页面证据。**Take ownership（接管）**、**Give to agent（交给智能体）** 以及智能体之间的实时交接，都属于明确的控制权变更。

关闭最后一个标签页不会删除已保存的工作区。空的工作区重启后仍会显示在侧边栏中，可用来打开新的、由用户控制的空白标签页。关闭 Xenon 也不会让网站退出登录：持久工作区会保留 Cookie，包括会话 Cookie。**Restore last session（恢复上次会话）** 在用户明确选择后，以用户控制权重载符合条件的已保存 URL，并排除隐私／受保护页面；它不会恢复未保存的表单状态、渲染进程内存或旧的智能体操作——要保留当前正在运行的页面，请改用实时交接。

原生 **Remove workspace（移除工作区）** 需要确认，且不能用于移除 Personal；它会关闭该工作区的标签页、取消下载，并撤销其授权。共享的凭据库账号、已完成的下载和原始上传文件仍会保留。配置文件清理范围有限，遇到锁定或不安全的路径时可能延后执行；这既不算安全擦除，也不等于网站退出登录。工作会话退役和关闭标签页是两个独立操作。

## Alpha 版本的边界

- **平台与宿主：** 支持 Windows x64 和外部本地 stdio MCP 宿主。只能远程连接的宿主需要其他传输方式；视觉任务需要支持图像的客户端／模型。不内置模型，不提供云同步或已签名安装程序，也不保证兼容专有 DRM 或任意扩展。
- **凭据：** 已保存账号功能只覆盖有限类型的 HTTPS 表单。MFA、通行密钥、CAPTCHA、嵌入式登录组件和特殊流程都需要用户处理。受保护身份验证期间不会返回观察结果／截图；原生 Save/Fill/Resume 确认无法通过 MCP 接受。测试夹具的覆盖不代表已完整验证真实鼠标键盘操作下的凭据提示，也不代表兼容所有真实网站。
- **文件与结果：** 不支持目录上传、File System Access API 选择器和跨框架委托文件选择器。选中文件不代表服务器已经收到文件；操作已派发也不代表网站任务成功。继续操作之前，请先检查结果不确定的操作和页面状态。
- **信任：** 所有网站文本、图像、对话框和下载名称都是不可信内容。过滤隐藏内容并不能让模型免于提示注入，也无法识别所有可见秘密。授权工作区就等于开放对应的页面会话。DPAPI 无法防御以同一 Windows 用户身份运行的恶意软件。本 Alpha 版本尚未经过独立安全审计。请阅读[安全边界](docs/SECURITY.md)。
- **更新与验证：** 更新需要用户决定安装并重启，且不会保留正在运行的渲染进程状态。发布的哈希依据发行元数据验证下载内容，不能证明发布者身份。合成测试和原生测试驱动的覆盖情况与实际界面操作覆盖分别记录；完整的菜单／对话框、高对比度和多 DPI 验收矩阵尚未完成。参见[测试说明](docs/TESTING.md)。

## 架构、构建与贡献

Xenon 使用 **C++20**、**CEF 的沙箱化 Chrome 运行时**、**原生能力代理**和**严格校验参数的 TypeScript MCP 适配器**。宿主通过 stdio 启动适配器，适配器再经由当前用户的 Windows 命名管道连接代理。客户端、工作区、控制权、账号和文件授权检查全部由原生代码执行。这里没有模型指定的 JavaScript、原始 CDP、隐藏 DOM 提取或操作系统控制接口。

准备好 Windows 10/11 x64、Visual Studio 2022 C++ Build Tools 及 Windows SDK／CMake、Node 24、npm、Git 和 7-Zip 之后（参见[前置条件](docs/BUILD.md)）：

```powershell
./scripts/bootstrap.ps1
npm.cmd ci
./scripts/build.ps1 -Test
./build/app/Release/Xenon.exe
```

请把匹配的运行时文件放在可执行文件旁边。参照 [TESTING.md](docs/TESTING.md) 选择适合本次改动的检查，并遵循[贡献者指令](AGENTS.md)。不要针对共享输出并发运行构建或桌面测试套件。
